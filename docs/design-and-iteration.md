# 为什么这样升级

目标是展示如何使用 AI Agent / Codex 把模糊研究需求转成可执行、可检查的交付物。投资是任务场景，不以代码数量、角色数量或模拟收益作为能力证明。

## 需求如何转成验收条件

| 用户需求 | 实现 | 可以检查的证据 |
|---|---|---|
| 融入自己的研究方法 | 趋势→路线→叙事→预期差→量化→赔率；六项明确的分析任务 | `showcase.review_prompt`、真实 `review.json` |
| 多个视角，而非泛泛介绍 | 产业、成长、预期差、宏观、质量、风险共同审阅同一证据包 | 每项事实引用或缺失证据，不允许空白冒充结论 |
| Agent 不只是一次聊天 | 第一轮联网研究；第二轮独立调用审阅；结构失败允许修复一次 | 原始事件、运行编号、被批评的原句和修订 |
| 判断价格是否合理 | 明确参数的五年FCFF、情景、敏感性、反向增长求解 | `valuation.py`、输入JSON、逐年现金流、恒等式与回代测试 |
| HR 能很快看懂 | 一页案例入口，方法、任务流、批评修订、证据和计算可展开 | `docs/index.html`；不是只有源码 |

“独立调用”是两个分别执行的模型请求，不是不同模型、独立专家或无偏共识。未证明第二轮一定优于第一轮，仍需人审。

## 方法来源与边界

六项问题是为这个项目编排的检查任务，不能当作完整复制巴菲特、林奇、马克斯或德鲁肯米勒的方法。当前版本不扮演这些人物，不声称他们评价了演示证券。后续只有在读到具体原始材料、能写明方法与适用边界后才添加人物归属。

估值工程参考现金流折现的一般框架和显式假设原则：[Damodaran 估值介绍](https://pages.stern.nyu.edu/~adamodar/New_Home_Page/background/valintro.htm)。现阶段只实现可审查的FCFF模型，没有为了凑多方法而添加缺乏可比数据的PE、SOTP或机械加权。

## 一次实际迭代

旧版本能检索、核验来源，但没有展示分析如何被审阅。升级后把“第二轮批评了哪条结论、如何修订、哪些输入仍缺失”直接放到案例页。任务未提供完整证券估值输入时保持“无法判断”，而不是让模型编一个目标价。

估值示例使用明确标记的虚构公司与数字，与真实AAPL/SPY研究分区。它证明程序确实执行计算，不证明这两只证券便宜或贵。任何真实证券输入还必须含报价日期、财务期间、币种、同单位股数和出处。ADR、ETF暂不进入普通股模型。

## 复现

```bash
# 完整运行：新联网研究 + 第二轮审阅 + 虚构输入的计算实验
python showcase.py --valuation-input examples/valuation-assumptions.json
# 复用公开且注明日期的证据，只调用第二轮；不会刷新旧事实
python showcase.py --research-file examples/research-packet.json --valuation-input examples/valuation-assumptions.json
python -m unittest discover -v
```

首次运行需要已登录Codex CLI，使用用户额度。不要将真实持仓配置、原始私人任务日志或投资观点直接提交到仓库。公开案例的事件摘要只保留工具类型、次数、运行编号等必要信息。
